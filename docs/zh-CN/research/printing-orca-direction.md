# Autumn Print：基于 OrcaSlicer 的 3D 打印工艺与生产 Agent

[English](../../en/research/printing-orca-direction.md) | 简体中文

> 方向确认（2026-10-29）：用户已认可 3D 打印工艺与生产助手方向。当前集成开发路线见 [guide.md](../engineering/delivery-plan.md)；本文保留为选题与源码调研依据。

调研日期：2026-10-29（Asia/Shanghai）。用户已明确行业方向为 3D 打印。本文件是产品建议与代码调研，不表示能力已经实现。未修改 OrcaSlicer，也未连接或控制打印机。

## 1. 建议定位

面向小型 FDM 打印工作室、打印农场和企业打样中心，帮助操作人员把一项打印需求从工艺准备、首件试打和验证，推进到批量生产、失败补打、验收齐套与交付追溯。

建议产品名：**Autumn Print — 3D 打印工艺与生产助手**。

用户提出需求并上传模型；应用读取机器、耗材和已验证工艺，用 OrcaSlicer 生成可比较的切片方案，组织试打与测量，记录经过确认的工艺条件，随后跟进生产和异常。

OrcaSlicer 承担模型处理与切片；Autumn 承担目标理解、计划、工具调度、试验记录、业务判断、协作与执行状态。底层执行数据必须来自实际工具或人员确认，不能由模型编造。

## 2. 为什么从这个方向切入

已有明确生态能力：

- [OrcaSlicer 官方仓库](https://github.com/OrcaSlicer/OrcaSlicer)提供配置、切片、校准及网络打印支持。
- [官方 CLI 文档](https://www.orcaslicer.com/wiki/cli/cli_mode)说明可无界面加载、变换和切片，支持自动化调用。
- [官方校准指南](https://www.orcaslicer.com/wiki/guides/calibration_guide)提供温度、最大体积流量、PA、流量系数和回抽等试验流程。
- [官方讨论 #8593](https://github.com/OrcaSlicer/OrcaSlicer/discussions/8593)中有用户自报将 3MF 模板、CLI 和打印农场 API 串联。讨论可作为实际使用线索，不能当作本项目已经完成相同兼容性验证。

同时需要正视现有覆盖：

- [Printago 云切片](https://docs.printago.io/docs/printing/cloud-slicer)已经按机型、工艺、耗材组合生成 G-code，并与队列匹配关联。
- [SimplyPrint 打印队列](https://simplyprint.io/features/print-queue)已经涉及多机匹配、排队、清床与继续打印条件。
- 视觉失败检测也已有 Obico、OctoEverywhere 等方案；具体证据见 [生态比较](printing-ecosystem.md)。

**产品判断：** 普通排队、远程按钮、自然语言修改参数都不足以单独支撑特色。值得验证的切口是把“试打—实物验收—工艺版本—批量任务—失败复盘”串成可追溯闭环，验证其是否确实改善目标用户的日常工作。尚未证明现有产品不能覆盖，也未验证客户购买意愿。

需求原始材料另见 [用户与工作流研究](printing-user-needs.md)。

## 4. 一笔贯穿 0–1 的业务（虚构）

某工作室收到 50 套卡扣支架订单，每套包含 1 个底座和 2 个卡扣。客户要求黑色 PETG、后天交付，卡扣需与指定配合件装配，接触面不应有明显支撑痕迹。

工作室有 3 台打印机、若干材料卷和历史工艺。首件是否计入交付，由订单与质量规则明确。

### 第一步：需求与模型检查

- 记录数量、用途、材料、颜色、外观区域、关键尺寸、配合件与交期。
- 建立零件清单与套件关系，确认实际需要 50 个底座和 100 个卡扣。
- 读取模型版本，核实单位、尺寸、平台容纳性和网格问题，形成需要人工确认的可打印性风险。
- 客户未给的承载指标、尺寸要求或材料替代许可不能由 Agent 自行补成已确认条件。

### 第二步：生成少量候选工艺并实际切片

- 从兼容的机器、喷嘴、材料和工艺配置出发，在允许范围内形成候选朝向、层高、壁厚和支撑方案。
- 由 OrcaSlicer 实际切片，保存参数差异、估算时间、耗材、警告与输出文件。
- 对照关键表面、装配方向、人工拆支撑和交期要求比较方案。
- 结构强度、尺寸公差和实际良率不能从流畅解释或切片时间直接推导。

### 第三步：首件试打与验收

- 给出试打目标和验收清单，操作者确认设备、材料和环境后执行。
- 收集首件照片、测量、装配反馈和异常；关键尺寸由实际测量记录确认。
- 若卡扣过紧，先检查实际尺寸、象脚、模型配合和相关工艺，形成可能原因及验证步骤。
- 在可复查范围内改变少量因素，对照试验；保留每次模型、配置、机器、材料及结果。
- 由负责人批准适用条件下的工艺版本。通过一次首件不代表对所有机器和材料永久有效。

### 第四步：批量生产

- 按零件数量、兼容设备、材料余量、可用时间和清床安排拆批。
- 只有符合已验证工艺适用条件的设备与材料组合进入计划；换喷嘴、换料或改模型时明确是否需重新验证。
- 每盘绑定订单、零件数、机器、材料卷、工艺版本和文件校验值。
- 批次状态区分待准备、可下发、打印中、待取件、待质检、合格、失败和返工。

### 第五步：异常与补打

- 某盘掉件或欠挤出后，结合图像、日志和人工确认标记受影响范围。
- 记录报废、待检与可用数量；只补有证据确认的缺口。
- 宏观失败图像用于异常提示与调查，不直接证明根因、隐蔽缺陷或尺寸合格。
- 需要更换机器或工艺时重新校验适用条件，不重复发送已经成功启动的任务。

### 第六步：齐套与交付

- 按质检通过数量核对 50 个底座和 100 个卡扣；打印任务总数完成不代表订单齐套。
- 记录后处理、装配与包装确认，保留各套件或批次追溯关系。
- 汇总计划与实际时长、材料消耗、人工和报废记录，形成复盘。
- 将有证据的经验作为适用范围明确的工艺记录，供以后相似订单参考。

## 5. 完整企业应用的模块

| 模块 | 具体用途 |
| --- | --- |
| 订单与套件 | 模型版本、数量、组件、验收要求、交期与变更 |
| 3D 检查与工艺规划 | 几何诊断、待确认风险、朝向/支撑候选与依据 |
| Orca 切片执行 | 配置解析、受控修改、真实切片、预览与估算比较 |
| 首件与试验中心 | 校准任务、试打、测量、装配反馈和审批 |
| 工艺与耗材档案 | 已验证条件、配置版本、机器/喷嘴/材料卷与变更 |
| 批次与设备任务 | 排产建议、准备条件、下发、状态与清床确认 |
| 异常与补打 | 故障证据、原因假设、对照验证、报废与缺口补打 |
| 质量与交付 | 逐件/抽检规则、合格数量、后处理、齐套与交接 |
| 团队与治理 | 操作者/工艺员/质检员权限、审批、审计、预算与凭据 |

多 Agent 可以按职责分工：需求核对、几何检查、工艺候选、试验分析、生产计划、质量复核。简单任务无需强制启动所有角色；它们共享任务与证据体系，不能把纸面结论当作物理动作已经发生。

## 6. 建议的集成方式

### 首期

Autumn 维护业务任务、试验、证据和成果；本地执行端通过固定版本 OrcaSlicer 完成文件与切片操作。前端可提供模型/切片成果和计划预览，原有 Orca GUI 用于人工检查与确认。

先做一次任务一个隔离目录，保留输入哈希、最终有效配置、引擎版本、输出文件和退出状态。配置继承应显式解析并校验，不能靠模型猜测参数名或机器能力。

### 后续

- 选择一个可测试的设备后端接入，比如在已授权测试环境核验 Moonraker 或 OctoPrint；其他品牌逐项实现能力矩阵。
- 上传文件、启动打印、暂停、取消和恢复分别建模，不能假设上传成功就是已开打。
- 通过审查的配置和 G-code 才能进入设备动作；设备准备、清床与装料需要真实确认。
- 若需要 Orca 内体验，再评估对应版本插件或最小集成；本次只看到本地 dev 目录存在插件代码，未验证发布版兼容。
- 复用 Orca 代码、打包分发或服务化前需核查其 AGPL-3.0 及相关组件许可证，本次不据调用方式推断法律结论。

## 8. 需要验证的特色与质量指标

潜在特色是“按明确条件验证并复用工艺，持续知道订单还缺哪些合格件、为什么缺、下一步谁处理”。需要和目标工作室现有切片/农场工具对比验证。

可度量：

- 切片任务能否复现，配置映射和警告是否正确。
- 估算与实际耗材、时长的偏差，而非只显示预测值。
- 首件通过所需试打次数、工艺变更依据是否完整。
- 异常漏报与误报、原因假设是否经验证。
- 合格数量与套件缺口是否准确，是否错误重复下发或补打。
- 关键步骤的人工投入、返工与报废记录是否可核验。

本轮仅完成源码和公开资料调研，尚未获得模型样本、设备清单、真实打印记录或实物试验结果。接下来的产品验证应从一台设备、一种材料和一笔可实测订单开始。
