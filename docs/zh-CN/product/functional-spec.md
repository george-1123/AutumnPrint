| F-02 | 模型连接 | 配置个人 API 地址/Key/模型 | 使用管理员授权模型 | 用户/管理员配置，系统检测 | 鉴权、不可达、能力不足分别提示；保存后不回显 Key |

| F-04 | 检查、修复与切片 | 支持 | 支持，指定现场端 | 几何/切片工具执行，用户接受修复 | 输入、配置、引擎和成果可追查；不支持项不显示通过 |
| F-05 | Agent 任务与候选比较 | 支持 | 支持，受组织策略限制 | Agent 提议、工具取证、用户补充 | 可查计划、证据、预算、等待、取消、错误及恢复 |
| F-06 | 首件试打与验收 | 本人记录确认 | 授权人员记录确认 | 人员执行、测量与判定 | 未测保持未知；打印完成不等于合格 |
| F-07 | 工艺与知识 | 本人工艺资料 | 企业授权工艺资料 | Agent 提议，人员批准 | 批准固定版本及条件，修改不覆盖历史 |
| F-08 | 设备、材料与动作 | 本机授权设备 | 企业登记现场设备 | 人员准备/批准，工具执行 | 动作状态与设备事实分开，未知结果先核查 |

| F-10 | 异常、补打与交付 | 支持 | 支持，按岗位授权 | Agent 分析，人员质检 | 合格缺口、版本和套件正确，重复处理不重复计数 |

## 首次使用与模型配置

个人使用：选择个人模式 → 创建工作区 → 填写模型连接 → 检测连接与必要能力 → 保存凭据引用 → 进入工作台。无效 Key、网络不可达、工具调用能力不足和取消配置分别呈现；失败不会丢失已创建资料，也不会改用模拟结果。

企业使用：填写企业服务器地址 → 登录 → 选择获准工作区 → 使用组织授权的模型与设备。模型 API 地址与企业服务器地址分别命名，不混用。管理员更改连接权限不改写既有任务证据。

## 任务和业务主线

导入订单/模型 → 补齐要求与单位 → 几何检查 → 必要时接受修复版本 → 实际切片比较 → 首件试打与实测 → 工艺批准 → 批次安排 → 待检/合格/返工/报废分类 → 补齐缺口 → 齐套与交付。

Agent 可提出计划和候选，确定性检查与工具返回事实，人员批准工艺及动作、完成实物判定。角色如何运行由[Agent 与工具设计](../architecture/agent-and-tools.md)规定。

任务应区分排队、执行、等待输入、等待现场结果、成功、失败和取消；外部动作结果未知独立呈现，不直接当失败重试。用户能查看下一步等待谁、证据在哪里和恢复条件。具体持久化及消息协议属于架构设计。

## 业务对象与规则

以下对象定义完整业务含义；统一术语以[CONTEXT.md](../CONTEXT.md)为准。

| 对象 | 最小含义 | 关键关系与边界 |
| --- | --- | --- |
| `Order / OrderLine` | 交期、零件数量、材料与验收要求 | 订单行指向明确模型版本；套件关系不能只存总件数 |
| `ModelRevision` | 模型原件、版本、哈希、单位与检查结果 | 修改或修复产生新版本，保留原件 |
| `Machine / MachineState` | 设备能力及当前观测状态 | 机型、喷嘴、固件等条件与实时状态分别记录 |
| `MaterialSpool` | 材料、颜色、批次、余量及状态 | 实际材料卷与抽象耗材配置分开 |
| `ProfileSnapshot` | 本次使用的完整有效配置 | 保存继承解析结果、来源和引擎版本 |
| `ProcessCandidate` | 待比较的工艺方案 | 所有改动有边界、差异和原因，尚未经试打批准 |
| `SliceRun` | 一次实际切片及输出 | 绑定输入哈希、配置、引擎版本、退出码、警告与估算 |
| `Trial / Inspection` | 试打及实测验收 | 照片、测量值、装配反馈、检查人和结论分开保存 |
| `ValidatedProcess` | 已批准工艺及适用条件 | 绑定通过的模型、设备条件、材料与验收证据 |
| `Batch / PrintJob` | 批次及具体设备作业 | 关联零件与计划数量；真实产出需另行核验 |
| `Incident / ReprintRequest` | 异常、受影响范围与补打 | 保留原批次和原因；按合格缺口计算补打需求 |
| `Approval / AuditEvent` | 对具体版本和动作的决定 | 参数或条件变化后复核，批准不代表设备动作已发生 |
| `Task / Step / Event` | Agent 任务、步骤与进度 | 会话、切片、打印、质检和订单状态分别建模 |

### 四个不能合并的事实

| 事实 | 证明什么 | 后续仍需确认什么 |
| --- | --- | --- |
| 切片成功 | 引擎生成了对应输出 | 设备条件、试打表现和实际质量 |
| 设备报告完成 | 本次设备作业结束 | 是否已取件、实际数量、外观和尺寸 |
| 首件检查通过 | 在记录条件下满足检查项 | 工艺对其他机器、材料或模型的适用性 |
| 订单可交付 | 合格零件已满足套件与数量要求 | 后处理、包装、交接等约定步骤 |

质量为待检的零件不能计为合格产出。相同实物从待检转合格只改变分类，不能重复增加总数量；返工、报废、撤销质检和旧版隔离同样需要可追溯记录。

## 贯穿全流程的验收样例

### 固定业务样例

一家工作室收到 **50 套黑色 PETG 卡扣支架**订单：

- 每套包含 **1 个底座和 2 个卡扣**，总需求为 50 个底座、100 个卡扣。
- 卡扣需要与指定配合件正常装配；记录由客户确认的关键尺寸和允许偏差。
- 接触面不应有明显支撑痕迹，具体检查方法由负责人确认。
- 有 3 台示例打印机和若干材料卷，其中一台刚更换喷嘴。
- 订单有明确交期、人员值守与清床时间。
- 首件是否计入交付由订单规则明确，符合条件才扣减剩余需求。

所有模型、设备和材料记录先使用合成或获准使用的样例。该样例用于演示普通功能件，不承诺安全关键用途的性能认证。

### 样例事件

1. 模型导入后发现尺寸单位需要确认。
2. 两个候选朝向在接触面支撑和打印时间上有取舍。
3. 首件打印完成，但卡扣装配过紧。
4. 调整后试打通过，形成适用条件明确的工艺版本。
5. 批量生产中一盘发生异常，部分零件待检、部分报废。
6. 客户更新卡扣模型，已排任务和旧版实物需要重新判断用途。
7. 补打与质检结束，按合格零件数量完成齐套交付。

同一订单贯穿以上事件；其他模型和材料用来验证功能可复用性。交付顺序见工程交付计划。
