## Agent 与现场执行的职责

业务 Agent 的代码在 `packages/control-plane/src/autumn_control/agent/`，由 `apps/worker` 运行；不在 Electron renderer、API 请求事件循环或现场端中进行推理编排。

| Agent 工作角色 | 业务职责 | 个人模式 | 企业模式 |
| --- | --- | --- | --- |
| 总控协调 | 核对目标、规划、委派、汇总与等待 | 本机 worker | 服务器 worker |
| 需求核对 | 数量、套件、材料、模型版本与验收缺项 | 本机 worker | 服务器 worker |
| 模型检查 | 调用几何工具、解释检查与修复差异 | 本机 worker | 服务器 worker |
| 工艺规划 | 生成受约束候选、请求真实切片、比较证据 | 本机 worker | 服务器 worker |
| 试验分析 | 首件反馈、假设、参数试验与适用条件 | 本机 worker | 服务器 worker |
| 生产规划 | 可行性检查、批次建议与进度跟踪 | 本机 worker | 服务器 worker |
| 质量复核 | 异常调查、数量核对、补打与交付建议 | 本机 worker | 服务器 worker |

这些是同一套工作流中的可配置角色，不要求每个角色独立服务。简单任务保持单角色；委派使用固定角色/图版本、受限工具、预算和证据。部署配置只替换数据、模型、身份、任务投递和现场连接 Adapter，不复制角色提示词与业务规则。

现场端 `apps/edge` **不是第二套业务 Agent**，无需独立模型 Key：它核验领取任务的授权、时效、文件 hash 与设备作用域，执行 Orca、几何检查/修复、设备读取和获准动作，并管理子进程、资源、文件、动作日志及回执。几何事实来自工具，审批与实物质量来自业务记录，现场端不自行决定工艺批准或补打数量。

运行关系图统一见[运行部署](runtime-and-deployment.md)。

## Agent、工具与业务完成条件

LangGraph 是唯一主图编排实现。总控、需求核对、模型检查、工艺规划、试验分析、生产规划和质量复核是同一套工作流中的角色，按需委派。个人所有角色在本机 worker 编排，企业所有角色在服务器 worker 编排；共享 `packages/control-plane` 中的图、角色版本、工具定义与评估。Edge 只执行受控工具，无独立推理编排。相同功能不承诺不同模型输出一致。

- 图状态存任务/成果引用、假设、缺项、计划与预算，不嵌入大模型文件、G-code 或全量照片。
- 工具通过类型化参数调用 Module Interface；读取与拟执行动作分开。
- Agent 可以提出修复、参数候选、试打、排产和设备动作，真正生效由业务策略、批准和 Adapter 执行。
- 设备凭据、对象存储密钥和任意网络/文件/Shell 能力不交给模型。
- 子 Agent 的权限为用户、组织策略、父任务授权、角色允许能力与设备能力的交集。
- 角色定义保存名称、指令版本、工具允许列表、输出结构、知识范围、模型配置引用、步数/并发/费用限制及启用状态。
- 管理页支持新建、编辑、禁用、发布版本和查看运行记录；正在执行的任务固定角色/图版本。
- 预算耗尽、证据不足、权限拒绝和等待实物都是明确状态，不能包装成成功。
- 模型路由按文本规划、视觉辅助和结构化核对配置；供应商能力须通过工具调用/JSON/图像样例验证，不能只凭“兼容”标签假设一致。

工艺知识与记忆分开：设备手册和历史记录可检索；“已批准工艺”只能由真实业务记录及批准产生，不能由自动记忆提取直接升级。
