# 验证计划

[English](../../en/engineering/validation.md) | 简体中文

本文件拥有工程测试层次、故障验证和发布检查；业务验收条件以[功能规格](../product/functional-spec.md)为准，初始化门槛以[bootstrap](bootstrap.md)为准。本地工程验证和剩余门槛见[开发启动指南](getting-started.md)，下列完整产品清单仍待验证。

## 测试、观测与性能验证

- 业务：pytest 覆盖套件、数量转换、修复接受、工艺批准、模型变更、资源授权与合格缺口。
- Adapter：Fake 与真实工具共用 Interface 契约；真实 Orca 固定样件测试输入、配置继承、警告、结果解析与取消。
- 数据：个人 SQLite 测数量事务、短事务竞争、本地队列、checkpoint 与备份恢复；企业在真实 PostgreSQL 测并发更新、租约、outbox、RLS 和迁移，两者不互相替代。
- 设备：先 Fake 故障注入，覆盖已启动但回执丢失、重复消息、外部占用、旧观测、清床未确认、失联切换。
- 桌面：Vitest/Testing Library 测界面和纯逻辑，Playwright 对 Electron 窗口关键路径测试；额外检查 IPC 来源、参数、文件范围和外链。
- 3D：固定尺寸、坐标、单位与多对象样件；预览截图不能证明制造模型正确或实物合格。
- 运维：个人队列与企业 broker 分别故障注入，API、worker、现场端分别退出/重启；关闭窗口、休眠、断网、模型连接失败及存储失败状态可追查，设备结果未知不会被重新开打。
- 双模式：同一业务/Agent 契约评估，干净机器个人安装即用、企业多用户授权、工作区切换、凭据隔离与显式迁移分别验收，详细清单见部署设计。

结构化日志和 OpenTelemetry 关联 organization/order/task/run/slice/job/action ID；记录调用、重试、延迟、引擎版本和 provider 实报用量。成本按带日期的价格配置计算并注明估算，敏感文件和设备密钥不进入遥测。

性能阈值待样件基准确定：模型字节/面数、预览首帧和窗口响应、切片并发/内存、事件补读、文件传输、观测延迟。当前没有经过测试的容量或质量承诺。

## 完整交付验收

- 干净 Windows 机器安装个人版，无 Python/Node/Docker/PostgreSQL/Redis，配置模型连接后完成订单、真实切片比较、历史查询；安装所需运行资源可离线获得。
- 使用相同 fixture/Fake 模型与工具，个人和企业通过同一业务及 Agent 契约评估；真实模型结果按证据/约束评估，不比较回复逐字一致。
- SQLite 与 PostgreSQL 分别验证事务、数量约束、迁移、并发恢复和备份；本地队列与 Celery 分别验证重复派发、崩溃、租约与取消。
- 关闭窗口、退出桌面、后台崩溃、休眠、断网和模型 API 失败后，任务状态可追查，设备启动不会被通用重试重复执行。
- 企业多用户授权、撤权、checkpoint、文件及事件流隔离通过；个人凭据、本地端点与工作区隔离通过。
- 个人/企业切换不串事件、不泄露 Key、不自动迁移数据或争夺设备；导出/导入保留引用与证据并重新核对批准。
- 本地安装/卸载、企业部署、签名更新、数据库与 checkpoint 升级及备份恢复分别演练；在途动作期间延后不兼容更新。
